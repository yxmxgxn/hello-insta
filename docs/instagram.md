# 投稿の取り方

ハロー！プロジェクトのメンバー・OG の Instagram の投稿を、どこから・どう取って D1 に入れているかのまとめ。
サイトを見る人向けの説明は [仕組み](https://insta.karin-archive.com/tech) にある。

## 取り方

| 取り方 | 対象 | 中身 |
|---|---|---|
| 公式API(Graph API の Business Discovery) | プロアカウント(ビジネス/クリエイター)の人 | `crawler/fetch.py`。毎時。いいね数・種類・持ち主まで取れる |
| 外部サービス(Apify) | 個人アカウントでよく投稿する人 | 毎日。終わったら Webhook で `POST /api/crawl/apify` |
| 取り込みページ | 個人アカウントの人の過去分など | `/import`(管理人用)。画面に出ている投稿を読んで登録する |
| 公式の埋め込み | 見るとき | 一覧の「▶ ここで見る」で Instagram 公式の embed.js |

どの取り方で入っても、同じ投稿は1件にまとまる(公式APIは Instagram のメディアID、それ以外は `web:<shortcode>`)。
個人アカウントの人がプロに切り替えたら、公式APIの分が `web:` の分を置き換える(最初に入った日時は引き継ぐ)。

## 対象

- karin-archive の SNS一覧の表で instagram がある人(現役 → J.P ROOM → UP-FRONT CREATE → UP-FRONT PROMOTION → その他のOG)。
  グループ公式アカウントと `EXTRA_ACCOUNTS` も入る
- `EXCLUDED` の人は外し、D1 からも消す
- 個人アカウントの OG は `PERSONAL_OG_KEEP` の人だけ残す。現役メンバーは個人アカウントでも対象

## 公式API(Fetch)

Cloudflare の Worker の定時実行が、毎時 GitHub Actions の Fetch を起動する(GitHub の schedule は控え)。1回の流れ:

1. **新着**: 新着を見る番の人の最新50件。1人1日1回(`LATEST_EVERY_HOURS`、既定24)。
   全員が同じ回に番になると回数制限に当たるので、1人ずつ「自分の時刻」を決めて1日の中に均等に散らす。
   `PRIORITY` の人は3時間ごと・一番先。個人アカウントの人は週1回だけ試す(プロに切り替えたら拾うため)
2. **遡り**: 残った回数で、過去分を50件ずつ古い方へ。「頼むデータが多すぎる」(code 1)と断られたら、
   件数と項目を減らして頼み直し、それでもだめならその人の遡りは打ち切る
3. **周回**: 遡りを終えた人の投稿を、別のカーソルで新しい方から最後まで読み直す(下)
4. Meta の回数制限(`Application request limit reached`)に当たったら、その回は終わり。続きは次の回

そのほか:

- 共同投稿: 持ち主(`username`)も聞き、持ち主が対象アカウントならその人の投稿にする。対象外の人が持ち主なら、前に入れた人のまま
- `media_product_type`(FEED / REELS)も聞いて `post.product_type` に入れる。聞けない項目は警告して外して続ける
- 返事の後ろに余計な文字が付くことがある(JSONDecodeError: Extra data)。前の部分だけ使う
- D1 が混んで 500(overloaded)が返ったら、間をあけてやり直す。本文が同じ投稿は索引(`post_fts`)を書き直さない(`cap_hash`)

## 周回(全部の読み直し)

- 1人 `ROUND_EVERY_DAYS`(既定7)日ごと、`PRIORITY` の人は毎日。1回の実行で使うのは `ROUND_CALLS`(既定10)回まで
  (回数制限まで使い切ると、次の回の新着が止まるため)
- 読み直しで、書き直された本文・いいね数・種類がそろう
- 公式APIの返事に入った投稿は `post.seen_at` を更新する。周回を読みきった人で、その周回の間に返ってこなかった投稿が
  **消えたかもしれない投稿**(周回で返った一番古い投稿より古いものと、周回を始めたあとの投稿は除く)
- 消えたかもしれない投稿は取り込みページと毎日の報告に出る。**自動では消さない。管理人が確かめて「消す」か「残す」**
  (年齢制限などで API が返さない投稿もあるため。「残す」は `post.keep = 1`)

## 数がずれる理由

- **サイトの方が多い**: 公式APIは、本人が共同投稿者になっている投稿もその人の一覧に返すが、
  プロフィールの「投稿 N件」はそれを数えない
- **サイトの方が少し少ない**: 持ち主が別の人の共同投稿は、持ち主の分に入る
